## Decisiones
Publicar la aplicación existente desde la raíz de main con GitHub Pages.
Usar autenticación de GitHub gestionada por su CLI; las credenciales no se
guardan en el proyecto. Confirmar cuenta y visibilidad antes de crear el remoto.

## Criterios de aceptación
1. El repositorio pertenece al usuario indicado y contiene el proyecto.
2. Pages sirve index.html, CSS, módulos y catálogo por HTTPS bajo la subcarpeta.
3. La web anuncia 98 preguntas y permite completar una partida.
4. La documentación contiene la URL comprobada y cómo publicar actualizaciones.

## Implementación y pruebas
Validar el proyecto, crear el commit inicial, crear y subir el repositorio,
activar Pages y verificar los recursos y un flujo de juego en la URL remota.

## Supuestos y límites
El usuario autentica su cuenta. Un repositorio público permite Pages con
GitHub Free; un repositorio privado depende del plan. El despliegue es asíncrono.
